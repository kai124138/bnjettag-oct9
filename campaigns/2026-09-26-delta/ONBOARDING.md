## 1. What Delta is

Delta (formerly "method atlas", renamed 2026-09-27 because "atlas" reads as the ATLAS detector) is
a pre-registered queue of **103 methods** to try on the binary {−1,+1}-weight N=64 tagger: 50 singles
(46 methods + 4 labelled non-binary baselines) and 53 combinations (31 packages + 22 cells of two
fractional factorials), across binarization, recipe, activation widths/EBOPs, architecture and
inputs. Each method is a change relative to the **Chang (Sun/Laatu et al.) recipe anchor** that the
training-batch campaign runs. Delta runs in waves; each wave has its own pre-registered STUDY.

| wave | what | status |
| --- | --- | --- |
| 0 | the anchor (training-batch campaign, other session) | its regime-B pilot is running |
| 1 | zero-GPU measurements (floors, caches, fingerprints) | mostly done inside PREFLIGHT |
| 2 | single-method screen, 500-epoch horizon, validation only | **STUDY frozen**, PREFLIGHT in progress |
| 3 | combination packages and factorial cells | designed, not started |
| 4 | confirm survivors: 7,000 epochs, 8 seeds, ROC-test once | designed, not started |

## 3. How a Delta cell gets from the catalogue to a GPU

1. `delta.json` → `code/generate_delta.py` writes one config per (entry, target, seed) on top of the
   anchor's own per-seed arm configs (arm A = E at 350k, A07-350, C = A07 at 5M) from anchor bundle
   **42abed4b**. `wave2_amendments.json` adds the frozen STUDY's placebos (P-350, P-5M, seeds 1-4) and
   replica seeds 1-8 (seeds 5-8 stop at epoch 500 in their configs).
2. `code/classify_series.py` runs the patched tree's strict validator on every config; `annotate_index.py`
   adds gate results. `configs/index.json` regenerates byte-identically from these three scripts.
3. Code: `code/apply_anchor.sh` = anchor bundle 42abed4b + `patches-anchor/0001-0038`. (`patches/`
   0001-0025 is the tarball series for the public repo.) Every Delta key is opt-in; with none set the
   tree reproduces the anchor bitwise (19/19).
4. `bundle/freeze_delta.py` packs tree + configs + packs into a ConfigMap. Current bundle:
   **705a554b8da0…c6f98**, ConfigMap `kai-delta0926-code-705a554b8d`, pod manifest sha 300be87b…467c.
   Create ConfigMaps with `kubectl create`, not `apply` (the annotation is too long).
5. `code/manifest_wave2.py` writes Jobs: t0 (the 20 replica arms, 8 pods), then cells (228 arms incl.
   the 8 placebos, 87 pods) after the replica gate. Each pod runs
   gate 15 (`fingerprint_check.py`: arm A s1 initial EBOPs must equal **11,559,681**) before any arm,
   and exports its pack's `BNJ_RSS_GATE_LIMIT_MB = 2,100 + 5 × H` MiB.
6. `run_pack.py` (anchor + Delta 0038) runs K arms per pod; W&B project `kayamaguchi-uc-san-diego/
   BNJetTag-Delta` (PRIVATE, verified); run ids are keyed by `BNJ_STAGE` + name, so canary and
   production runs never share an id.
