# Configs

The two run configs live in the code repository, because the Job reads them from the code bundle.
The files here are symbolic links to them:

- `code/campaigns/d350/configs/d350-baseline-e-350k-s1.json`, sha256 `0e3c5454…b609`
- `code/campaigns/d350/configs/d350-reference-e-5m-s1.json`, sha256 `c0b65395…049b`

Both were generated by `code/campaigns/d350/generate.py` at code commit `d4f6659`. Neither was
edited by hand. The generator rebuilds the pilot config `pilot1005-h1-e-350k-c-s1` (sha256
`2d0bff42…c6`) with the pilot's own generator, checks it byte for byte against the pilot file,
and asserts an exhaustive flattened diff. That diff is recorded per config in
`code/campaigns/d350/config_map.json`.

Every other key is identical, including seed 1, split seed 1, order seed, batch 2,790, LR 3e-3,
cosine restarts every 500 epochs, the PID gains, option (c) (`pid_input: traced_only`, per-epoch
integral), warmup 1, trace every 10 epochs, checkpoints every 25, snapshots every 500,
the 0-bit floor 171,526 and `train.epochs` 7000. The reference config also equals the pilot's own
E-5M rung, `pilot1005-h2-e-5m-c-s1`, apart from identity keys; the generator asserts this.

## Stop epoch: not a config key

The pilot stopped at epoch 500 with `run_pack.py <pack> 500`. That passes `--stop-after 500` to
`run_study.py train` and then to `ablation.run_training(stop_after=…)`, which saves a checkpoint
at the pause and returns. `train.epochs` stayed 7000. This campaign uses the same mechanism with
`run_pack.py <pack> 1000`, set in the Job by `tools/prepare_attempt.py --stop-epoch`
(default 1000). The config hash therefore does not depend on the stop epoch. Because of that, a
run can resume to a later stop epoch, which the follow-up stage needs; `code/tests/test_d350.py`
checks that this resume reproduces a straight run.

With `snapshot_every_epochs` 500, the runner writes `snapshots/epoch-0500/` and
`snapshots/epoch-1000/`. The epoch-1000 snapshot coincides with the pause. The score reads both.
