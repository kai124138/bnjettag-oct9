## 1. Hypothesis

In the baseline every binary projection computes `y = beta * (x @ sign(w - mean(w))) + bias`, with
one analytic scalar `beta` (absmean) per kernel (`bnhgq2/qat.py`, `bitnet_binary_ste`, lines
45-67). Every output channel of a layer therefore has the same weight magnitude, and the network
can set a channel's size only through its sign pattern. A learned scale per output channel lets it
weight channels unequally (BiViT, arXiv:2211.07091, Sec. 3.3.2, "parameterized weight scales":
channel-wise scales act as channel importance). The hypothesis is that this extra freedom keeps
validation accuracy when the EBOPs controller narrows activation widths to reach 350,000 EBOPs.

## 2. Rationale and the chosen form

- Wave 1: the baseline has no feasible checkpoint in 1,000 epochs
  (`INVALID[scientific]: no feasible checkpoint in epochs < 1000`); the 5M reference is valid
  (0.6497741935483871, validation, n = 62,000, unverified, from its epoch-30 checkpoint). PROPOSAL
  §7 makes C1 and C2 the first candidates; C2 is not yet specified.
- Why powers of two. A real-valued per-channel scale is a constant multiply on every output
  element: 11,293 per jet over the nine binary layers of model E (from the config shapes:
  input_proj 64×24, Wq/Wk/Wv 64×2×12 each, Wo 64×24, ffn_fc1 64×32, ffn_fc2 64×24, head_fc1 24,
  head_fc2 5). Priced at even 2 bits × 8 bits each, that is about 180,000 EBOPs, more than the
  178,474 EBOPs between the 0-bit floor and the target (`campaigns/d350/index.json`,
  `headroom_zero`). That is an arithmetic estimate, not a trace, but it means a real-valued scale
  could not meet the budget at all. A power-of-two multiply `2^k` on a fixed-point value moves the
  binary point: wiring, no logic. Its cost at its actual precision is zero, and the
  value change it causes is priced downstream by the existing quantizers, whose widths the
  controller already traces.
- Departure from BiViT: BiViT's scales are real-valued and initialised by the analytic rule (the
  initialisation is UNVERIFIED in `notes/methods-C1.md`). Here they are powers of two, initialised
  to 1, on top of the existing per-tensor `beta`. Nothing below depends on an UNVERIFIED item.
- What would argue against it (record, do not act on): the learned exponents stay at 0; or they
  move but the run still has no feasible checkpoint; the reference shows a similar accuracy loss
  at 5M, so a mechanism tied only to narrow widths may not be the cause.

## 5. Required behaviour

### 5.1 Config

New key `quant.weight_scale`, absent in every existing config:

```json
"weight_scale": {"kind": "per_channel_pow2", "k_min": -4, "k_max": 4}
```

- Absent or `null`: current behaviour, no new variables.
- Any other value: `ValueError` naming the config, unless `kind == "per_channel_pow2"`, integers
  `k_min < 0 < k_max`, and `quant.weight == "binary_absmean"`.

### 5.2 The scale

For each of the nine binary layers (`input_proj`, `bit_block_0_attn_Wq/Wk/Wv/Wo`,
`bit_block_0_ffn_fc1/fc2`, `head_fc1`, `head_fc2`; `ablation.expected_binary_layers`):

- A trainable float32 latent `theta` named `c1_channel_scale`, created in `build()` with
  `add_weight(name="c1_channel_scale", ..., initializer="zeros")`. A constant initializer draws
  no random numbers, so every kernel equals the baseline's at the same seed.
- Shape: the output channel axes. For `BitQDense`, `(units,)`. For `BitQEinsumDense`, the axes of
  the output subscript that also appear in the kernel subscript, in output order:
  `btf,fd->btd` gives `(D,)`; `btd,dhe->bthe` gives `(H, E)`; `bthe,hed->btd` gives `(D,)`;
  `btd,df->btf` gives `(FFN,)`. It broadcasts against the output with the leading batch and
  particle axes.
- Forward, training and inference alike:
  `k = round_ste(clip(theta, k_min, k_max))`, `m = 2 ** k`,
  `y = (x_q @ bitnet_binary_ste(w)) * m + bias`, then the activation.
  `round_ste(t) = t + stop_gradient(round(t) - t)`. The multiply comes after the binary
  contraction and before the bias. At inference `m` is exactly a power of two.
- Gradient: `dy/dtheta = y_pre_bias * ln 2` inside `[k_min, k_max]` (the STE passes through the
  rounding), zero outside the clip range. The kernel's gradient path is unchanged.
- At initialisation `theta = 0`, so `m = 1` exactly and the model output equals the baseline
  model's output bit for bit at the same seed and inputs.
- Serialisation: add the setting to the layer constructor (`channel_scale=None` or the dict) and
  to `get_config()` only when it is not `None`, so a baseline layer's config is unchanged. Keep
  `@keras.saving.register_keras_serializable(package="bnhgq2")`; a saved `.keras` file must
  reload with the scale.
- Put a comment `# d350-inference-op: c1_channel_scale` on the line that applies `m`.

### 5.3 EBOPs and certification

- The EBOPs computation is protected and is not edited. The scale is inside the existing binary
  layers, so the per-layer EBOPs that HGQ2 computes from the input quantizer bits and the 1-bit
  kernel pin are unchanged by it. That is the correct price of a power-of-two multiply (zero), and
  the claim rests on `m` being exactly `2^k` with integer `k` at inference; the tests check it.
- What the scale changes downstream (the value ranges seen by the next quantizers, hence their
  traced integer bits and their trained widths) is priced by the existing trace. Nothing is
  hidden from `ablation.model_ebops`.
- Declare the operation in the config: `campaign.candidate.inference_ops: ["c1_channel_scale"]`.

### 5.4 Training loop (`bnhgq2/train.py`), flag on only

- Exclude every `c1_channel_scale` variable from Adam weight decay
  (`optimizer.exclude_from_weight_decay(var_names=["c1_channel_scale"])` or equivalent). The
  learning rate, clipping and schedule are unchanged.
- Diagnostic (the mechanism's own signal for the slow-starter rule, PROPOSAL §5): at every
  traced epoch (the existing `ebops_trace_every` cadence) append one JSON line to
  `<run dir>/channel_scales.jsonl`:
  `{"epoch": <zero-based>, "layers": {<name>: {"n": .., "k_hist": {"-4": .., ..., "4": ..},
  "frac_nonzero_k": .., "theta_mean": .., "theta_abs_max": ..}}}`.
  On resume, truncate it to the committed epochs exactly as the run's other per-epoch files are
  truncated (see `ablation.py` near line 325, `truncate_jsonl`).
- With the flag off, nothing in `train.py` behaves differently and no file is written.

## 6. Tests

`tests/test_d350_c1_channel_scale.py` (CPU, small inputs, `KERAS_BACKEND=tensorflow`):
1. Flag off: building the baseline config gives the same weight names, shapes, values and
   parameter count as the baseline at commit 43e8326 (compare against a model built without the
   key); no variable named `c1_channel_scale` exists.
2. Flag on, at init: model output equals the flag-off model's output exactly (same seed, same
   input batch); every kernel equals the baseline kernel.
3. Shapes: each of the nine layers has one `c1_channel_scale` of the shape in §5.2.
4. Binary weights: `qat.effective_weight_values(model)` still gives exactly two values per layer,
   symmetric, no zero; `ablation.binary_gate(model, cfg)` passes with the flag on.
5. Power of two: after setting `theta` to values such as -4.7, -0.6, 0.49, 2.5, 3.2, 9.0, the
   inference-mode `m` equals `2**k` with integer `k` in `[-4, 4]`, exactly (`log2(m)` is an
   integer).
6. Gradient: one training step on a batch gives finite, non-zero gradients for `theta` inside the
   clip range and zero for an entry set outside it; the kernel gradients stay finite.
7. Save and reload `.keras`: same outputs, same `theta`.
8. Weight decay: with the flag on, the optimizer built by `train.py` excludes the scale latents
   from weight decay and still decays the kernels; with the flag off, the optimizer is configured
   as before.
9. Diagnostic: a two-epoch CPU run on a tiny sample (or a direct call of the writer) writes
   `channel_scales.jsonl` rows with the §5.4 fields; resume truncation keeps only committed
   epochs; with the flag off no file is written.
10. Config errors: an unknown `kind`, `k_min >= 0`, or a non-binary weight type raises
    `ValueError`.

`tests/test_d350_c1_certification.py` (the harness requires this name; it must mention
`certify_ebops`, `model_ebops` and `c1_channel_scale`):
1. On the C1 config's model built on CPU with a fixed sample, `ablation.model_ebops(model)` (what
   the PID controller reads) equals `ablation.compute_ebops(model, X)['total']`, and
   `certify_ebops.certify_checkpoint` on a saved checkpoint returns `CERTIFIED` with the logged
   value equal to the retraced one. Load `eval/certify_ebops.py` by file path from
   `os.environ["D350_EVAL_DIR"]` and restore `sys.path` afterwards.
2. Hand count on a one-layer example: a single `BitQDense` with a fixed input quantizer, with and
   without the scale, given the same quantizer state: its `ebops` equals the hand-computed
   sum of input bits × 1 over the products, and the two values are equal (the power-of-two
   multiply adds 0).
3. With `theta` set so that `k != 0` in some channels, the per-layer EBOPs of the scaled layer is
   unchanged for identical quantizer state, and the total traced EBOPs differs from the `k = 0`
   model only through downstream quantizer widths (assert that the scaled layer's own entry is
   equal and report which layers changed).
4. The `c1_channel_scale` variables are inside layers that `ebops_calc.compute_ebops` already
   iterates (`enable_ebops` true), so no added inference operation sits in an uncounted layer.
