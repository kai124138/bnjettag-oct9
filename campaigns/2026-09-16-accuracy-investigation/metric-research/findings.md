Accuracy/AUC audit, 2026-09-16

The recorded best completed arm is channel quantization: validation accuracy 58.8879%, held-out accuracy 58.7431%, validation macro OvR AUC 0.851884, 317,890 EBOPs. These figures come from publication/results/post_conference/ablation_metrics.json; they are existing evaluation evidence, not a new inference run. The 0.145 percentage-point validation/test accuracy gap does not suggest a large generalization collapse.

Accuracy and AUC answer different questions. Accuracy checks whether the largest of five class scores is correct. Each OvR AUC ranks examples of one class against all other examples, and macro AUC averages these five rankings. An AUC of .85 does not imply 85% correct multiclass predictions. The local synthetic test constructs normalized five-class probabilities with AUC exactly 1.0 and accuracy .20, proving the quantities need not coincide. Definitions: [scikit-learn AUC](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html), [scikit-learn accuracy](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.accuracy_score.html).

The same gap appears in closely related physics research: Odagiu et al. report 64.6% accuracy for an eight-constituent MLP alongside class AUCs 0.84, 0.88, 0.90, 0.88, 0.92. Their Deep Sets model rises from 64.0% at eight constituents to 75.9% at 32. Different splits, preprocessing and models prevent a direct performance comparison. Their work also documents the resource/latency tradeoffs of more constituents and notes linear constituent scaling for Deep Sets versus quadratic interactions. [Primary paper, Table 1](https://arxiv.org/html/2402.01876v2).

Concrete code findings:

- publication/code/hgq2/bnhgq2/train.py:58 computes exact per-class sklearn ROC AUC, averaged with nanmean. No apparent AUC/accuracy formula bug. Its callback at :169 and optional early stopping at :183 select AUC only.
- Before this patch, ablation.py logged training-batch categorical_accuracy alongside independently evaluated val_macro_auc, without validation accuracy. Comparing those epoch fields mixed populations and evaluation modes. Published accuracy is a separate correctly implemented argmax evaluation, not this logging confusion.
- Before this patch, ablation.py feasible checkpoint selection maximized AUC, not accuracy. Actual records show objective disagreement: reduced FFN has higher validation AUC (.854457 versus channel .851884) but lower validation accuracy (.585234 versus .588879).
- Train and evaluation loaders agree on sorted files, explicit class order [g,q,W,Z,t], stable descending pT order, top-N selection and exact feature suffix resolution. Standardization uses training-only statistics. No obvious ordering mismatch in the inspected code. Dataset contents and prediction alignment still require runtime checks.
- Current constrained configurations use eight particles, three features, binary weights, learned activation widths and no normalization. Information truncation and strong quantization are plausible performance constraints, not demonstrated sole causes. publication/README.md records eight-particle FP32 AUC .8864 versus W1A8 .8712; larger input configurations improve AUC but increase cost. Attention softmax precision already has an ablation; its recorded accuracy does not beat channel quantization.

Low-cost solutions:

1. Log validation accuracy from the existing validation inference and allow validation-accuracy checkpoint selection within the same EBOP budget. No extra model inference is needed. This is implemented only in ablation.py in this workspace.
2. Fit class-specific logit biases on validation predictions; compare with regularized vector scaling using a separate validation selection fold, and report final performance on untouched test predictions. Biases can in principle fold into the existing floating-point output bias in qat.py's head_fc2, avoiding additional runtime arithmetic; exported fixed-point effects need verification. Scalar temperature scaling is useful for confidence calibration but cannot change argmax accuracy. Guo et al. explicitly derive that invariance and describe validation-fitted vector/matrix scaling. [Primary calibration paper, section 4.2](https://proceedings.mlr.press/v70/guo17a/guo17a.pdf).
3. If calibration does not help, compare stored feasible checkpoints by validation accuracy, then consider targeted head refinement or resource reallocation before full retraining. More particles/precision should be justified by measurements; EBOPs alone do not establish latency, FPGA area or timing closure.
