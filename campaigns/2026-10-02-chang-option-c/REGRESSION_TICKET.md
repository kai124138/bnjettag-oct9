## Root cause
Test-environment leakage: tests/test_run_pack.py:40 inherits the whole process environment, and the cpu-gate Job exports BNJ_CAMPAIGN_DIR (campaign root) before pytest, which overrides run_pack's default of "own directory". Not a product bug in run_pack.py or in the option-(c) changes; the training pods set the same variable correctly and want it. Confidence: high (about 90 percent) for the mechanism (log shows real arm names; reproduced locally by toggling the one variable); the exact staged-tree history is unverified.

## Minimal fix
Either, preferred (test-only, one line): in tests/test_run_pack.py setup(), add `BNJ_CAMPAIGN_DIR=str(tmp)` to the env dict at line 40-42 (and keep env.update(extra) after it). Alternative (no code change): in freeze_c.py gate script run pytest with `env -u BNJ_CAMPAIGN_DIR -u BNJ_RUN_ROOT -u BNJ_DATA_ROOT python -m pytest ...`. Note run_study-importing tests may rely on those variables, so prefer the test-only fix. Also worth a check: test_attn_entropy.py:159 uses monkeypatch.setenv, so it is already safe.
