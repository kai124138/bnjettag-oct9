## TL;DR
The paper LogicNets itself explicitly credits as introducing the "pack the whole neuron into one truth table, no exposed datapath" architecture (LogicNets' own Fig. 1b). Trains a dense, activation-quantized (binary-activation-only) network, then uses **Boolean logic minimization** (treating unreached input combinations as "don't-care" conditions, per Karnaugh-map-style ISF — Incompletely Specified Function — reduction) to compress each neuron's truth table, rather than restricting fan-in via sparsity a priori the way LogicNets does.

## (a) Mechanism
Standard NN training (dense, not sparse) with binary activation quantization → convert each trained neuron into a Boolean function of its (dense, hence potentially high-fan-in) inputs → apply a **lossy** logic-minimization/ISF pass that only fixes output values for input combinations actually seen in training data, leaving the rest as don't-cares for the synthesis tool to optimize away → synthesize the resulting reduced truth tables to LUTs. LogicNets' own paper (§II-B, verbatim) draws the precise mechanistic contrast: *"NullaNet only considers densely connected networks and suffers from high fan-in... NullaNet uses a lossy truth table sampling method to overcome the fan-in problem which gives an approximation of the DNN, whereas we [LogicNets] use a lossless method... NullaNet only considers binary quantization of activations."*

## (b) What it explicitly does NOT do
- **Not a checkpoint compiler** in our sense either — still requires training its own dense, binary-activation network specifically for this pipeline (the "don't care" minimization step depends on which combinations the *specific trained network* actually visits during training), not an arbitrary already-trained network of unconstrained precision.
- **No attention/matmul/sequence-model support** — MLP-only, same as the rest of the family.
- **Binary activations only** in the original formulation (LogicNets' explicit point of comparison) — narrower precision flexibility than LogicNets/PolyLUT/NeuraLUT's multi-bit options.
- **No Jet Substructure Classification (JSC) numbers found**, and — unlike LUTNet, where absence is only inferred — here we have a **direct, explicit primary-source reason for the exclusion**, stated by NeuraLUT's own paper (§IV-B, verbatim): *"NullaNet [9] cannot be a direct point of comparison since it implements the first and last layers in floating-point and reports hardware results only for the hidden layers."* NullaNet is accordingly absent from every JSC comparison table checked this session (LogicNets, PolyLUT, NeuraLUT, AmigoLUT, NeuraLUT-Assemble all omit it from their JSC rows even though most discuss it in related work).
- Original NullaNet/NullaNet-Tiny benchmark tasks (MNIST, SVHN, CIFAR-10-scale image classification per its own framing as a "reduced-memory-access" successor to XNOR-Net-style BNN work) — **not independently confirmed against the primary PDF this session** (only abstract-level text fetched); mark specific dataset list as **UNVERIFIED**, though the "why it's excluded from JSC tables" reason above is a direct primary-source quote from NeuraLUT, not an inference.

## (c) Exact published jet-tagging numbers
**None found**, and (uniquely among the 8 systems surveyed) there is a **direct, stated methodological reason** from a downstream primary source, not just silence.

## Verdict
**ADJACENT.** Architecturally a direct ancestor of LogicNets' "no exposed datapath" design point, and cited as background by every later paper in this family, but never evaluated on JSC and explicitly disqualified from JSC comparison by NeuraLUT's own text due to its floating-point boundary layers. **ORTHOGONAL** to compiling a given trained transformer: dense-but-still-bespoke-trained, binary-activation-only, no attention/sequence capability, no externally-pretrained-checkpoint path.
