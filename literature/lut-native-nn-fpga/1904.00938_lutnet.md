# LUTNet: Rethinking Inference in FPGA Soft Logic (+ IEEE TC extension)

- **Authors:** Erwei Wang, James J. Davis, Peter Y. K. Cheung, George A. Constantinides — Imperial College London.
- **Venue / Year:** Two companion papers, same core idea:
  - Conference: **FCCM 2019** (27th IEEE Int'l Symp. on Field-Programmable Custom Computing Machines), San Diego, May 2019, pp. 26–34, doi: 10.1109/FCCM.2019.00014. **arXiv: 1904.00938.**
  - Extended journal version: **IEEE Trans. Computers, vol. 69, no. 12, pp. 1795–1808, Dec 2020**, doi: 10.1109/TC.2020.2978817, titled *"LUTNet: Learning FPGA Configurations for Highly Efficient Neural Network Inference"*. **arXiv: 1910.12625.**
  (Both arXiv IDs and the FCCM→TC relationship confirmed directly from three independent primary bibliographies read this session — LogicNets ref [7], PolyLUT ref [4]/[15], AmigoLUT refs [15]/[16] — which cite them as the same lineage, conference-then-journal-extension.)
- **PDF:** https://arxiv.org/pdf/1904.00938
- **Code:** https://github.com/awai54st/LUTNet
- **Topic area:** LUT-native neural networks for FPGAs

## TL;DR
Precursor to LogicNets. Observes that an FPGA K-LUT can implement *any* K-input Boolean function, not just XNOR — so replaces a binarized neural network's (BNN's) XNOR-popcount operations with **learned, trainable K-input Boolean functions** ("LUTNet-style" logic), reaching high LUT density and ~1.81× mean area reduction vs. BNNs at ±0.3 pt accuracy on standard vision benchmarks. Still has an **explicit accumulation/popcount and activation datapath outside the LUT** (LogicNets' Fig. 1a "weights in LUT equations" category) — this is the key structural difference from LogicNets/NullaNet/NeuraLUT, which pack the *entire* neuron (weights + accumulation + activation) into one truth table with no exposed datapath.

## (a) Mechanism
Takes a pruned, residually-binarized network (built on ReBNet) and, per LUT, replaces the XNOR + a piece of the popcount with a **learned K-input Boolean function** trained via a Lagrange-interpolating-polynomial relaxation (a differentiable proxy for the discrete truth table) — i.e. training and LUT-structure are co-designed, exactly like the rest of this family: the sparsity pattern (which activations a LUT reads) is fixed a priori by random selection with replacement (`x_r`, `x_r'` in the paper's own Fig. 1a notation), and the LUT contents are learned by backprop through the interpolation, not compiled from an independently-trained dense network.

## (b) What it explicitly does NOT do
- **Not a "given checkpoint" compiler** — same as the rest of the family: a specific sparse/binarized topology must be built and trained end-to-end with LUTNet's own training loop; there is no route from an arbitrary pretrained dense or ±1 transformer checkpoint into LUTNet hardware.
- **No attention/matmul/sequence-model support** — evaluated exclusively on **CNV (CIFAR-10, 86.29% accuracy, 61M LUT-equivalent logic elements per one WebSearch-derived secondary summary — UNVERIFIED against primary PDF this session, flag before quoting), and AlexNet/ImageNet** — standard CNN vision benchmarks, not sets/sequences/particle physics.
- **No Jet Substructure Classification (JSC) numbers found.** Checked LUTNet's own reference position in five independent, JSC-comparison-table-building papers read this session (LogicNets Table II, PolyLUT Table IV, NeuraLUT Table III, AmigoLUT Table 4, NeuraLUT-Assemble Table IV) — **LUTNet never appears as a JSC data point in any of them**, even though all five discuss it architecturally in their related-work sections. This is strong converging (though not 100%-certain without a direct primary-PDF experiments-section read) evidence LUTNet's own paper reports no JSC/particle-physics numbers at all.
- **Parameter count scales exponentially with LUT input bitwidth** — confirmed directly from PolyLUT's own Table I/II: LUTNet's parameter count is `O(2^(βF))` ("Exponential" scaling type), the worst of the three scaling laws PolyLUT tabulates (LogicNets: `O(F)`, linear; PolyLUT: `O(C(F+D,D))`, polynomial-for-fixed-D). PolyLUT explicitly states this "proves feasible only in the context of binary activations" for LUTNet.

## (c) Exact published jet-tagging numbers
**None found.** Not evaluated on JSC by the original authors, and never cited with a JSC number by any of the five downstream comparison papers checked this session.

## Verdict
**ADJACENT** — an important architectural ancestor (learned-Boolean-function-per-LUT idea) that the rest of the family (LogicNets, NullaNet, PolyLUT, NeuraLUT) explicitly positions itself against/beyond, but it never touched the JSC task and its exponential-in-bitwidth parameter scaling is exactly the failure mode LogicNets was designed to avoid. **ORTHOGONAL** to "compile a given trained transformer": still a co-training method for a specific, small, sparsity-constrained topology, with no attention/sequence capability and no CIFAR-10-to-particle-physics precedent in its own paper.
