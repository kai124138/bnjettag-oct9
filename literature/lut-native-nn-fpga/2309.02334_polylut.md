# PolyLUT: Learning Piecewise Polynomials for Ultra-Low Latency FPGA LUT-based Inference

- **Authors:** Marta Andronic, George A. Constantinides — Dept. of Electrical and Electronic Engineering, Imperial College London.
- **Venue / Year:** FPT/ICFPT 2023 (Int'l Conf. on Field Programmable Technology), Yokohama, Dec 2023, pp. 60–68, doi: 10.1109/ICFPT59805.2023.00012.
- **arXiv:** 2309.02334 — https://arxiv.org/abs/2309.02334 (full text read directly this session, all 9 pages)
- **Code:** https://github.com/MartaAndronic/PolyLUT
- **Related follow-up (NOT this paper — do not conflate):** arXiv:2501.08043, *"PolyLUT: Ultra-low Latency Polynomial Inference with Hardware-Aware Structured Pruning"* (2025) — adds a hardware-aware structured-pruning stage on top of the same core idea; cited by NeuraLUT-Assemble as ref [9] with different (generally better) JSC numbers than the original FPT 2023 paper's Table IV below. **Downstream papers sometimes cite "PolyLUT" numbers from this pruned 2025 extension rather than the original — verify which PolyLUT paper a cited number actually comes from.**
- **Topic area:** LUT-native neural networks for FPGAs

## TL;DR
Generalizes LogicNets by replacing each neuron's *linear* transform with a **multivariate polynomial of tunable degree D**, evaluated inside the same fixed-size truth table (no extra multiplier hardware — the multiplication is absorbed into the enumerated LUT contents, same trick as everything else in this family). Because a higher-degree polynomial fits training data with fewer layers, PolyLUT reaches LogicNets' accuracy with a shallower network (fewer clock cycles) and 1.76–2.29× lower latency / up to 2.69× fewer LUTs than an equal-accuracy LogicNets baseline, on JSC and two other tasks.

## (a) Mechanism
Same co-design loop as LogicNets (built explicitly on its toolflow, Fig. 4): fixed a-priori random sparsity restricts each neuron to `F` inputs at `β` bits; **during training**, each neuron's input vector is first expanded to *all monomials up to degree D* (feature-vector size grows from `F` to `C(F+D,D)`, Eq. 2), then a standard linear+activation layer (Brevitas QAT) is applied to the expanded vector; **after training**, the whole neuron (expansion + linear + batchnorm + quant activation) is enumerated into one `β·F`-bit-input L-LUT, identically to LogicNets. `D=1` is mathematically equivalent to LogicNets (confirms PolyLUT is a strict generalization, not a different mechanism).

## (b) What it explicitly does NOT do
- **Not a checkpoint compiler.** Trained end-to-end from scratch per architecture/degree, exactly like LogicNets — no path for an externally pretrained network.
- **MLP-only**, no attention/sequence mention anywhere in the text.
- **Parameter count still exponential in fan-in F** for fixed structure (Table I: `O(C(F+D,D))`, "polynomial for fixed D" but the underlying L-LUT truth-table size is still `2^(βF)` — the exponential wall is unmoved, only the *training* parameter count and required *depth* improve). Their own conclusion (§V, verbatim): *"the L-LUT size still scales exponentially, limiting network architectures with few inputs, each of low precision."*
- Explicit trade-off noted for wide-fan-in cases: at JSC-XL, "our approach does not use DSP blocks at all, however it can result in a large LUT count in specific cases where both a high neuron fan-in and high precision is required to reach a given accuracy" (Table IV footnote discussion).

## Fan-in used
Per **Table III** (their own architecture table), fan-in `F` for the JSC task is **F=3 or F=4** across JSC-M-Lite / JSC-XL (with an input-layer exception `β₀=7, F₀=2` for JSC-XL) — **not ~6**; F=6 is used for their MNIST (HDR) architecture instead, and F=7 for the NID-Lite input layer. Fan-in is per-task-tuned, small (3–7) in every case.

## (c) Exact published jet-tagging numbers — Table IV, primary PDF, verbatim
JSC = "16 substructure properties to classify 5 types of jets" (their own §IV-A3 wording), citing Duarte et al. 2018 as the task's origin. Target device **xcvu9p-flgb2104-2-i**, Vivado 2020.1, `Flow_PerfOptimized_high`, Out-of-Context, clock period 1.6 ns (small nets) / 2 ns (large nets).

**Case study (§IV-C):** on JSC-M's 5-layer architecture, sweeping polynomial degree D=1..6 and eliminating layers shows a 2-layer, D=3 polynomial network matches a 4-layer, D=1 (=LogicNets-equivalent) network's accuracy (71.79% vs. 71.78%) at **2.29× lower latency and 2.69× lower LUT usage** (Fig. 7/8).

**Important internal literature discrepancy resolved this session:** AmigoLUT's own Table 4 (FPGA 2025) mis-quotes the JSC-M-Lite row's accuracy as **75%** at the identical 12,436-LUT/773-FF/5ns/646MHz operating point; both PolyLUT's own Table IV (above) and NeuraLUT's independently-authored Table III (citing PolyLUT as ref [7]) agree on **72%** for this exact resource point. Treat AmigoLUT's "75%" at that specific row as a transcription error; **72% is the primary-source-verified number.**

## Verdict
**OCCUPIES** the same MLP/JSC space as LogicNets, at a better latency/LUT operating point via polynomial neurons — reinforces "JSC-as-MLP is solved." **ORTHOGONAL** to compiling a given trained transformer: still whole-network co-training with a hand-fixed sparsity pattern, no attention, and an explicitly-acknowledged exponential LUT wall in fan-in that the authors themselves flag as the paper's core limitation.
