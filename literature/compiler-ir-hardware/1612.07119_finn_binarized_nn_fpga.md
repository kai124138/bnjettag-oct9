# FINN: A Framework for Fast, Scalable Binarized Neural Network Inference

- **Authors:** Yaman Umuroglu, Nicholas J. Fraser, Giulio Gambardella, Michaela Blott, Philip
  Leong, Magnus Jahre, Kees Vissers
- **Venue / Year:** FPGA 2017 (ACM/SIGDA Int'l Symposium on Field-Programmable Gate Arrays)
- **arXiv:** 1612.07119 — https://arxiv.org/abs/1612.07119
- **PDF:** https://arxiv.org/pdf/1612.07119
- **Code:** https://github.com/Xilinx/finn
- **Topic area:** compiler / IR / hardware backends

## TL;DR
The original FINN paper. Binary weights + binary activations map to **XNOR + popcount**
per Matrix-Vector-Threshold Unit (MVTU/MVAU) processing element (PE); parallelism is set by
folding factors PE (output/neuron folding) × SIMD (input/synapse folding), a
**weight-stationary, output-stationary time-multiplexing** of a physical compute unit across
neurons — the same conceptual axis as our "token-axis folding" proposal, just applied to the
neuron/synapse axis rather than the sequence/token axis.

## Key methods / contributions
- Bipolar (`{-1,+1}` via `{0,1}`) encoding turns each weight×activation multiply into an
  XNOR, and the row-sum (accumulation) into a popcount — this is a *per-PE* arithmetic
  reduction, not a cross-neuron/cross-row sharing scheme; we found no statement (in the parts
  of the paper we could extract via search-summary; direct PDF fetch failed twice, page-image
  encoded) that FINN applies any adder-graph/MCM-style common-subexpression elimination
  *across* PEs or weight rows — each PE independently reduces its own operand set via
  XNOR-popcount.
  **UNVERIFIED via direct primary-source quote** (PDF unreadable through our tooling this
  session) — corroborated only via WebSearch-synthesized secondary description; treat with
  that caveat.
- Folding: total execution cycles for a layer scale as `max(MH/PE, MW/SIMD)`-style products
  (`MH`=neurons, `MW`=synapses/neuron); FINN's `SetFolding` transform balances PE/SIMD choices
  per layer so the whole multi-layer streaming pipeline has a matched/balanced II — this is a
  genuinely **streaming-throughput** design (a dataflow pipeline of per-layer stages), not a
  single fixed-latency combinational/fully-unrolled pass.

## Main results
On a Xilinx ZC706, <25 W total system power: **12.3 million image classifications/s, 0.31 µs
latency, MNIST, 95.8% accuracy** (fully-unrolled MLP case); **21,906 classifications/s, 283 µs
latency, CIFAR-10/SVHN (80.1%/94.9% accuracy)** for a deeper CNN (source: WebSearch synthesis
of the paper/secondary sources — direct PDF quote not obtained this session, flag as
lower-confidence on the exact wording though the numbers are widely repeated).

## Relevance to BNJetTag
FINN's PE/SIMD folding is the field's canonical "weight-stationary time-multiplex a physical
adder/XNOR-popcount unit across neurons" pattern — structurally the same idea as our proposed
token-axis folding, just folding the wrong axis for us (neurons/synapses, not the 10-token
sequence axis of a fixed-shape attention layer). FINN's own latency numbers (0.31 µs MNIST,
283 µs CIFAR-10) show it comfortably hits trigger-adjacent latencies for small models but is
architected as a *streaming pipeline*, not fixed-latency-native the way hls4ml `io_parallel`
Latency-strategy RF=1 is — every FINN design is some folding factor's worth of cycles, and the
framework's whole design-space-exploration story (`SetFolding`, balanced pipelines) is about
choosing that folding, not eliminating it. See also: FINN has **no native attention/transformer
support in the mainline `Xilinx/finn` repo** — that exists only in the Paderborn University
`eki-project/finn-plus` fork (see FINN-T, FPT 2024) — mirrored in our own note under
`hls4ml-fpga-triggers` findings on hls4ml's own MHA-mainlining timeline.
